# 水滴观测站 · 内容生产 SOP（标准作业流程）

**版本**：v1.1
**日期**：2026-09-27（v1.1：角色拆分，见《多Agent分工方案》）
**定位**：本文件是每一篇文章从选题到发布的**可执行操作手册**——谁、在什么节点、做什么、产出什么、卡点在哪。规划文件（内容系列架构/选题库/排期）回答"写什么"，本文件回答"怎么跑"。
**角色分工**：见 [`多Agent分工方案.md`](多Agent分工方案.md)——主编（小迪）编排，采集/写手/编辑/质检/美术/运营六个专项角色执行，关键环节角色隔离（写手与质检员必须不同上下文）。

---

## 〇、总览：一篇稿件的流水线

```
【周中】采集简报 → 老板圈选题 → 【T1 素材采集】
      → 【T2 初稿撰写】→ 【T3 老板注入思想】→ 【T4 编辑整理】
      → 【T5 质检（四道工序）】→ 【T6 配图与排版】→ 【T7 预览与终审】
      → 【T8 推草稿箱】→ 【老板手机端确认发布】→ 【T9 发布后复盘】
```

**角色分工（铁律不变）**：小迪 = 主编（编排与调度，不亲自写稿/质检）；采集员/写手/编辑/质检员/美术/运营 = 专项 Agent（详见《多Agent分工方案》）；老板 = 选题圈定、思想注入、终审与发布——**三个不可省略的人节点**（圈选题 / 注思想 / 终审发布）。

---

## T1 · 素材采集（采集员 Agent-S，自动+人工混合）

**触发**：老板圈定选题后；热点周报类则每周五自动采集。

| 内容类型 | 采集动作 | 产出 |
|---|---|---|
| 热点切入类 | 抓取选定热点的一手信源（官方博客/论文/仓库 Release）+ 二手讨论（HackerNews、头部公众号 2-3 篇） | 素材包：原文要点、时间线、争议点 |
| 实测类 | 明确实验环境（工具版本、模型配置、任务集）；先跑通最小用例 | 实验记录：版本清单、原始数据、失败截图（脱敏） |
| 洞察思考类 | 收集支持/反对论点的证据各至少 3 条 | 证据清单（正反都要，防确认偏误） |

**素材入库规则**：所有素材存 `04_素材与配图/文章编号-素材/`，每条标注来源 URL 与采集时间。**无来源的素材不入库，无入库的素材不进稿**——这是 Q3 证据质检的前置条件。

**脱敏检查（T1 就做，不拖到质检）**：出现公司名/项目名/客户名/真实数据，当场替换为"某通信设备商""某版本"级模糊指称。

---

## T2 · 初稿撰写（写手 Agent-W）

- 依据：`01_定位与文风/` 两册基准文件 + 选题对应的系列规范
- 结构标准：三句内进题；小标题即论点；结尾三件套（互动问题+下期预告+资料钩子）
- **初稿必须留"注入位"**：每个论点后面显式标出 `[注入位：老板的观点/案例]`——把需要老板思想的位置预先挖好，不是写完了让老板自己找地方改
- 交付：`03_稿件/编号-标题/编号-标题-初稿.md`

## T3 · 思想注入（老板，人节点）

老板对初稿做三类动作，任选粒度：
1. **批注回传**（推荐）：直接在稿上改/批注，改完发回
2. **口述要点**：说一段想法，小迪按想法重写关键段落
3. **金句重述**：只重写核心论断和金句（10 分钟档）

> 老板没碰过的稿子不发——这是账号的灵魂保险丝。

## T4 · 编辑整理（编辑 Agent-E）

合并老板改动：顺逻辑、补引用、查事实、统一术语，产出 `发布版草稿`。此时稿件内容冻结，进入质检。

---

## T5 · 质检（质检员 Agent-Q，标准固化，与写手上下文隔离）

> 质检不是"感觉不错"，是逐项打勾。四道工序定义在《文风与排版手册》，此处是**执行规程**：

### Q1 语言质检（机械项，可脚本化）
逐项扫描，命中即改：
- [ ] 套话清单：说白了/这意味着/值得注意的是/总而言之/首先其次最后/不禁让人
- [ ] 标点堆砌（连续破折号、省略号超过 1 处/段）
- [ ] 教科书开头（"随着…的发展""在…时代"）
- [ ] 营销号腔（"震惊""颠覆""必看"）

### Q2 结构质检
- [ ] 第一段三句内进题？
- [ ] 小标题全部是论点句（不是"二、分析"这种目录式标题）？
- [ ] 段落节奏：无超过 8 行的段落？
- [ ] 结尾三件套齐备？

### Q3 证据质检（本号生命线）
- [ ] 每个关键论断能指认证据类型（实测/公开引用/构造场景）？
- [ ] 构造场景全部标注"构造"？
- [ ] 引用有出处？
- [ ] 数据可复现（实测数据在素材包里能找到原始记录）？
- [ ] **内容审核**：脱敏复查（公司/项目/客户/数据细节零泄漏）+ 合规红线复查（不涉现实政治、不判现实是非、AI 内容按平台要求标识）

### Q4 观测者终审
- [ ] 终审问句："读者读完，感觉是一个工程师在展示他的观测记录，还是一个资讯号在搬运信息？"——答不出前者，回炉
- [ ] 老板注入的思想还在稿里（没被编辑整掉）？

**质检记录随稿归档**：质检通过后在稿件末尾附质检记录（四道各一行结论），作为发布依据。**未过质检的稿子不进 T6**。

## T6 · 配图与排版（美术 Agent-A，T5 通过后进场）

**图片怎么选**（延续《001 配图方案》确立的分类，此处固化为决策顺序）：

1. **首图**：套用品牌视觉 v2 的统一模板（宇宙黑底 + 水银悬滴，每期只换一个元素）——**程序化生成，不用 AI 渲染**；导出时用**高清版**（`04_成品/封面_公众号_高清_1800x767.png`，官方推荐的 900×383 在手机上会被拉伸放大而发糊）
2. **结构/数据图**：需要准确文字的图一律**代码画或编辑器原生表格**，不用 AI（防乱码）
3. **案例/实测截图**：只来自老板的真实素材（脱敏后），**AI 不伪造实验现场**
4. **工具/文档截图**：官网引用，注明出处
5. **结尾签名图**：固定视觉资产

**选图否决线**：图与正文论点无关 → 删；拿不准的图 → 不放（图宁缺毋滥，观测站读者不为美图而来）。

**排版参数**：16px / 行距 1.85 / 段间距 1.45em / 短段落（单段不超 6 行）/ 金句加粗每篇 ≤3 处 / 配图占位标记此时全部替换为成品图。

**正文主题**：统一用 `05_运营与数据/主题/dropseer.css`（品牌视觉 v2 对齐版：白底墨字 + 灰度层次 + 一条琥珀细线；**去掉内置主题的蓝底色块**）。
用法：`wenyan publish -f 稿件.md -t lapis -c 05_运营与数据/主题/dropseer.css`。
注意：`-c` 是**替代**内置主题而非叠加，且 wenyan 内联器不处理根元素 `section`，故该 CSS 已把每个元素的字号/行高写全——**改动它时要逐个元素核对，别只改一处**。

## T7 · 预览与终审（老板，人节点）

- 排版稿渲染成预览发老板；老板手机实际预览一次（公众号最终呈现以手机端为准）
- 老板点头 = 发布许可；改动意见回 T4

## T8 · 推草稿箱（美术 Agent-A，半自动；发布凭证最小授权，仅此环节使用）

- 工具：wechat-publisher（wenyan-cli：Markdown → 公众号格式，图片自动传图床，推草稿箱）
- 前置条件：**公众号 AppID/AppSecret 已配置 + IP 白名单已加**（2026-09-27 已打通，四个门槛全部实测通过；操作见 `05_运营与数据/推草稿箱操作手册_v1.md`）
- **推送前先跑一次自检**：`bash 05_运营与数据/check_wechat_ready.sh`（一条命令报出凭证/白名单/接口权限状态，并把错误码翻译成下一步动作）
- 未配置凭证时走"一键复制模式"：`wenyan render` 生成排版预览页，老板手动粘贴到公众号编辑器
- 推送成功后回报：草稿箱链接 + 上传图清单

## 发布（老板，人节点，永远手动）

- 老板在手机公众号后台：过一眼 → 点发布（约 10 秒）
- **此节点永不自动化**——平台 2026-03 起严打非真人自动化创作，人工确认既是合规要求，也是账号保险丝

## T9 · 发布后复盘（运营 Agent-O，发布后 48 小时）

- 抓取数据：阅读/完读/点赞/转发/关注转化，存 `05_运营与数据/编号-数据.md`
- 对照健康线（完读 ≥30%、点赞 ≥2%、转发 ≥5%）标注达标情况
- 一句话结论回写选题库（该选题方向的验证结果，指导后续选题）

## 附一：内容审核 checklist（Q3 内嵌执行，单列备查）

| 风险 | 检查项 | 红线 |
|---|---|---|
| 脱敏 | 公司/项目/客户/真实数据 | 零泄漏，模糊指称代替 |
| 合规 | 现实政治、现实人物评判 | 不碰 |
| 合规 | AI 生成标识 | 按平台要求标注 |
| 版权 | 引用他人文章/图 | 署名+链接；截图注明出处 |
| 事实 | 关键数据 | 双源交叉验证或标注单一来源 |
| 商标 | 提及工具/公司名 | 正常署名可，不做贬损性对比结论 |

## 附二：当前流水线的两个缺口（诚实声明）

1. **T8 全自动推草稿箱未通**：等公众号凭证配置（AppID/AppSecret/IP 白名单）。通之前用一键复制模式过渡
2. **T1 热点自动采集未挂定时**：采集能力已具备（实测跑通过），定时简报等老板确认节奏后用 automation 挂上

## 附三：各环节耗时预估（单篇，周更节奏）

| 环节 | 耗时 | 谁 |
|---|---|---|
| T1 素材 | 1-2 小时（自动为主） | 采集员 |
| T2 初稿 | 1-2 小时 | 写手 |
| T3 注思想 | 30-60 分钟 | **老板** |
| T4 编辑 | 30 分钟 | 编辑 |
| T5 质检 | 30 分钟 | 质检员（独立上下文） |
| T6 配图排版 | 1 小时 | 美术 |
| T7 终审 | 10-15 分钟 | **老板** |
| T8 草稿箱 | 5 分钟 | 美术（凭证授权环节） |
| 发布 | 10 秒 | **老板** |
| T9 复盘 | 15 分钟 | 运营 |

主编（小迪）全程编排与跟踪，不计入单篇工序耗时。

**老板单篇净投入 ≈ 1 小时**，符合副业节奏；全流程从选题到发布 ≤ 5 天（热点类压缩到 48 小时内，蹭热度窗口）。
