# 水滴观测站 · 多 Agent 分工方案

**版本**：v1.0
**日期**：2026-09-27
**定位**：《内容生产SOP》的**角色拆分方案**——SOP 定义"九道工序怎么做"，本文件定义"每道工序谁来做"。核心原则：**单一角色不包揽全程，关键环节角色分离**。

---

## 一、为什么要拆

1. **质检独立性**：写手不能审自己的稿——同一个人写+审，套话和逻辑漏洞会互相看不见。评审必须换一双"新眼睛"
2. **上下文隔离**：采集 Agent 读了几十篇热点，判断会被污染；写稿应该只面对干净的素材包
3. **可追责**：每道工序有明确责任人，出错时能定位是素材错了、稿写歪了还是审漏了
4. **可替换**：某个角色表现不佳可以单独换掉/升级 prompt，不影响其他环节

## 二、角色设置（六个 Agent + 一个老板）

| 角色 | 代号 | 职责范围 | 对应工序 | 纪律 |
|---|---|---|---|---|
| **主编（编排）** | 小迪 | 总调度：接收老板指令、派工、跟踪进度、汇总汇报、维护项目库与记忆 | 全程协调 | **不亲自写稿、不亲自质检**——既当裁判又当运动员是分工要防的第一件事 |
| **采集员** | Agent-S | 素材与热点采集：跑信息源清单、整理素材包、执行脱敏、标注来源 | T1 | 只交素材不写观点；无来源不入库 |
| **写手** | Agent-W | 初稿撰写：按文风手册+系列规范写稿，预留注入位 | T2 | 只用素材包里的证据，不自行编造；不接触原始热点噪音 |
| **编辑** | Agent-E | 合并老板思想、顺逻辑、补引用、统一术语 | T4 | 老板注入的内容一个字不能丢 |
| **质检员** | Agent-Q | 四道质检 + 内容审核 checklist，逐项打勾出报告 | T5 | **与写手必须隔离**（不同会话/不同上下文）；只对标准负责，不对写手的辛苦负责 |
| **美术** | Agent-A | 首图生成、结构图绘制、排版渲染、推草稿箱 | T6/T8 | AI 图只做氛围不做内容；实测截图只收老板真件 |
| **运营** | Agent-O（可并入小迪） | 发布后数据抓取与复盘回写 | T9 | 数据只记录不美化 |
| **老板** | 人 | 圈选题、注思想、终审、点发布 | T3/T7/发布 | 三个不可省略的人节点不变 |

> 运营 Agent 工作量小（发布后 48 小时一次），前期由小迪兼；量大后再独立。

## 三、关键隔离规则（本方案的灵魂）

1. **写手 ↔ 质检员隔离**：质检员拿到的是**成品稿件 + 质检标准**，不拿写手的写作思路说明——避免被"作者的解释"带偏
2. **采集员 ↔ 写手隔离**：写手只面对采集员整理好的素材包（含来源、时间线、争议点），不直接泡在原始信息流里——防止选题判断被热点情绪污染
3. **美术 ↔ 质检分离**：配图在质检**之后**进场（T5 过了才 T6），避免"图都做完了"绑架文字修改决策
4. **发布凭证最小授权**：推草稿箱的公众号凭证只给执行 T8 的会话用，主编、写手等环节一律不接触
5. **老板节点不可被 Agent 替代**：任何角色都无权越过 T3/T7 直接推进发布

## 四、交接物与验收标准（流水线的"接口契约"）

| 交接 | 交接物 | 位置 | 验收方 | 验收标准 |
|---|---|---|---|---|
| 老板→主编 | 选题指令 | 对话 | 主编 | 说清系列/热点/截稿时间 |
| 主编→采集员 | 采集任务单 | 对话派工 | 采集员 | 含选题、素材类型、脱敏要求 |
| 采集员→写手 | 素材包 | `04_素材与配图/编号-素材/` | 主编转交 | 每条有来源 URL；脱敏完成 |
| 写手→老板 | 初稿（含注入位） | `03_稿件/编号/` | 老板 | 三句内进题；注入位齐备 |
| 老板→编辑 | 批注版/口述要点 | 对话回传 | 编辑 | — |
| 编辑→质检员 | 发布版草稿 | `03_稿件/编号/` | 质检员 | 内容冻结声明 |
| 质检员→美术 | 质检通过报告 | 稿件末尾附档 | 主编 | 四道全过 + checklist 全勾 |
| 美术→老板 | 排版预览 + 草稿箱链接 | 预览页 | 老板 | 手机端实际看过 |
| 老板 | 点发布 | 公众号后台 | — | 永远手动 |

## 五、两种运行模式

**模式 A · 串行手动派工（现在就能跑）**
老板对小迪下指令 → 小迪按工序顺序逐个"扮演"角色执行，但**每换角色就换一次会话/清空上下文**（保证质检隔离）→ 关键节点回找老板。适合当前单篇节奏。

**模式 B · 多 Agent 团队（量起来之后）**
用多 Agent 并行协作机制把六角色各设为独立 Agent，主编负责任务分发与汇总。适合：①热点周报（采集可日跑）②GUI Agent 实测系列（采集员盯 Release + 写手并行赶稿）③未来日更。

> 落地建议：001–005 用模式 A 把流程跑顺（每道工序的 prompt 在实战中固化），006 起切模式 B。**先用串行验证工序接口，再并行提效**——和测试流水线的道理一样：先通再快。

## 六、各角色启动 prompt 要点（固化用）

- **采集员**：「你是水滴观测站的素材采集员。只采集整理，不写观点。每条素材必带来源 URL 与采集时间，涉及公司/项目/客户信息当场脱敏。产出素材包存 04_素材与配图/。」
- **写手**：「你是水滴观测站写手。只使用素材包内的证据，写作前必读 01_定位与文风 两册。每个论点后留注入位。套话清单里的词一个不用。」
- **质检员**：「你是水滴观测站质检员，与写手无利害关系。按四道工序+内容审核 checklist 逐项打勾，产出质检报告。你的产出是"过/不过+原因"，不是修改建议优先——先判死活，再说怎么改。」
- **美术**：「你是水滴观测站美术。AI 图只做氛围不做内容，带文字的图代码画。实测截图只用老板提供的真件。质检未过的稿子不接。」

## 七、与 SOP 的关系

- 《内容生产SOP》v1.1 起，各工序的"（小迪）"标注全部改为本方案的角色标注
- 本方案变更角色设置时，同步改 SOP 对应节，两文件保持一致
- 角色分离是**纪律**不是形式：哪怕实际都是小迪在跑（模式 A），换角色时也必须换上下文——"我没受过污染"这句话，只有新会话才有资格说
