## 一、栏目设计：六个栏目，一句话各自是什么

| # | 栏目 | 是什么 | 频率 | 在 IP 里的角色 | 现状 |
|---|---|---|---|---|---|
| 1 | **热点周报** | 热点搜集+整合，站长筛选点评 | 每周六早（固定档） | 曝光入口（看见） | 采集管道已跑通，试刊待发 |
| 2 | **洞察思考** | 自己的思考、见解、反共识判断 | 月 1–2 篇 | 观点被转发，让人记住你（认出） | 001 初稿 v0.2 待注入 |
| 3 | **技术实战** | 个人实操+经验复盘 | 每 1–2 周 1 篇 | 真数据立信任（信任） | 002–007 已排，其余待启动 |
| 4 | **团队转型** | 带队心得与总结 | 月 1 篇 | 心路共鸣，筛铁粉（跟随） | 009 已排 |
| 5 | **读者案例** | 读者来稿的失效案例分析 | 不定期（攒够 5 个出 1 期） | 社区连接（连接） | 001 已埋钩子，暂无稿 |
| 6 | **同行访谈**（储备） | 同行对话 | 不定期 | 圈层连接 | 5000 常读后启动 |

**命名规则**（已定案）：内容是什么就叫什么，四字为主，不造词、不用隐喻。**意象进文章，朴素进标签**——文里可以用"观测/标本/黑盒"，合集标签只用大白话。

### 各栏目的结构模板与纪律

**1 热点周报**
- 结构：本周信号 5–8 条（**事实一句话 + 站长点评一句话，点评必须带测试/质量视角**）→ 编辑部动向 → 下周观测预告
- 纪律：不做全量搬运、不做没有点评的信息罗列（个人号写资讯必死）
- 分工：AI 干采集，老板干筛选与点评 → **价值不在信息量，在"站长选了什么、怎么看"**

**2 洞察思考**
- 结构：认知反转开头 → 框架展开 → 反共识判断（标注"这是我的判断"）→ 开放问题收尾
- 纪律：每篇必须有**一个原创框架或反共识判断**；纯综述不发这个栏目，降级进周报
- 代表：001 四层失效分类学、008 杰文斯悖论×测试、003 Agent 上班谁当 QA

**3 技术实战**（五条线，见下节）
- 纪律：不编数据（观测协议贯穿所有实测线）；构造场景必须声明；工作素材脱敏

**4 团队转型**
- 结构：真实带队场景切入 → 现象与证据 → 判断与取舍（含走过的弯路）→ 给同岗人的可操作建议
- 纪律：不写管理鸡汤、不写空泛趋势论；**允许写失败的尝试**（写踩坑比写方法可信十倍）

**5 读者案例**
- 结构：读者投稿 → 站长按四层框架归档分析 → 定期汇编
- 冷启动：前几期先用公开渠道的失效案例（GitHub issue、竞品文）填充示范格式，标注来源

**6 同行访谈**：轻量替代是"读者案例 + 站长回信"，先练对话感。

## 二、内容规划：骨架是"四大支柱 × 六个栏目"

### 四大内容支柱（主题维度）
1. Agent / MCP 链路实测
2. AI 端到端评测与质量度量
3. 质量范式思考
4. 组织与人的转型

### 技术实战的五条线（本号最重的栏目）
| 线 | 定位 | 弹药 | 排期 |
|---|---|---|---|
| GUI Agent 实测 | **测 Agent**——观测别人造的 Agent | 15 期 | 002/004/005/006/007 已排 |
| E2E 测试实战 | **用 Agent**——用 Agent 干测试主业 | 17 期 | 无（信任期后启动） |
| 评测工具横评 | 同需求多框架代码级对比 | 10 期 | 010 |
| 基线档案 | **测时间**——固定任务集重跑，画退化曲线 | 10 期 | 随 002 启动积累 |
| 测试 Agent 设计 | **造 Agent**——亲手设计与技能化 | 13 期 | 无 |

叙事弧：**测 Agent → 用 Agent → 造 Agent**。

**一鱼三吃切分规则**：写实操细节 → 测试 Agent 设计；写思想判断 → 洞察思考；写团队推行 → 团队转型。

### 节奏与启动顺序
- 周节奏（上限）：周六早 = 周报固定档 + 周中 = 主线篇轮换。**每周 2 篇是上限**
- 第一个月：001 → 002（browser-use 首测）→ 周报试刊 → 003（等实测数据期间补位）
- 前三个月：技术实战攒 3–5 篇真数据 + 周报档期跑顺

### 弹药库
120+ 期选题（约两年量）：GUI 实测 15 / E2E 实战 17 / 评测横评 10 / 基线档案 10 / 测试 Agent 设计 13 / 洞察思考 13 / 团队转型 12 / 周报 10+ / 读者案例 11 / 同行访谈 10。

### IP 认知漏斗（内容分工的底层逻辑）
看见（周报）→ 认出（洞察）→ 信任（实战）→ 跟随（转型）→ 连接（读者案例/访谈）。

## 三、复核意见：五条

### ⚠️ 1. 六个栏目里，三个是"将来时"——能立刻跑的只有四个
读者案例（要投稿）、同行访谈（要 5000 常读）、E2E 测试实战（文档写"信任期后启动"）。
**建议**：在排期文件里明确"前 8 周只启用 4 个栏目（周报/洞察/技术实战/团队转型）"，别让新读者看到空合集标签。空栏目比没有栏目更伤。

### ⚠️ 2. 结构性错配：最不可搬运的内容被排到了最后
- GUI Agent 实测：15 期、已排 5 期，但它是**观测别人的工具**——可抄、时效性最强（工具一升级，半年后文章就发黄）
- E2E 测试实战（17 期）+ 测试 Agent 设计（13 期）：**全网几乎无人从通信 E2E 视角写**，这才是"人物"这条护城河，却都标"无排期"

**建议**：把 **E.1（用 Agent 跑 E2E 全链路，人设开篇）** 提到 002–003 之间或紧随 002，作为"人物资产"的早期投资。GUI 实测横评（007）收官后再回到 E2E 主线，节奏更稳。

### ⚠️ 3. 每周 2 篇对一个人是重负担，但降级没有触发条件
文档写了"量力降为 1+1 隔周"，但没写"什么情况下降"。
**建议**：定死阈值——**连续 2 周未按档发布，自动转双周档**，并把周报降为每两周一次。写进 SOP，避免靠自觉。

### ⚠️ 4. 基线档案是复利资产，但必须和 002 同时落地
固定任务集要在 002 动手前就定稿，否则 002 写完了数据仍不可横比，后面全要返工。
**建议**：002 开工前先产出《观测协议 · 任务集 v1》（导航/表单/弹窗/Canvas/多步流程），并把它做成"可复现交付物"（这是资料钩子的第一份硬货）。

### ⚠️ 5. 漏斗写清了，但缺"每期固定动作"
认知漏斗（看见→认出→信任→跟随→连接）是战略，没有落成动作。
**建议**：补一张**每期固定动作清单**——周报每条热点带一个主线篇内链；主线篇末尾固定"上期观测回看 + 配套资料钩子"；读者案例每期回一封站长信。这样五个栏目才会互相喂流量，而不是五个平行博客。

## 五、一句话总结

**栏目设计已经收敛（六个朴素栏目 + 四支柱 + 五线技术实战），内容规划的量也够（120+ 期）。**
**真正的问题不在"设计得不够"，而在"顺序与产能"**：最独特的两条线（E2E 实战、测试 Agent 设计）排在最后，最能抄的那条排在最先；每周 2 篇的产能假设没有降级阀。
把 E.1 提前、定死降级阈值、002 前先固化任务集——这三件做完，规划就从"好看"变成"能跑"。
