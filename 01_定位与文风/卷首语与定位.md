## 名字定案（2026-09-28）

**名字：今知先生** ✅ 已查重，未被占用

**出处**：《水浒传》第一一九回《鲁智深浙江坐化 宋公明衣锦还乡》——鲁智深听钱塘江潮信而大悟，沐浴更衣、写颂坐化：

> 平生不修善果，只爱杀人放火。忽地顿开金绳，这里扯断玉锁。
> 咦！钱塘江上潮信来，**今日方知我是我**。

**为什么是它**

- 它不是自造词，是这句偈子的前半截——**今日方知**，**我是我**；
- 它恰好是本号**写作用目的**的文言版：费曼学习法、输出倒逼输入、写着写着才认出自己怎么想。"我不是一开始就知道自己在想什么，写下来才慢慢认出来。"
- 释读（学界通行）：禅宗常用语，指**认清自己的本来面目**（与苏轼"小舟从此逝，江海寄余生"意通）。

**配套三件**

| 项 | 取值 |
|---|---|
| 名字 | **今知先生** |
| 副题 | 用 AI 一边做事一边学 |
| 落款 | **今日方知我是我。**（备选：半解，然后比昨天多解一点） |
| 固定栏目（一对） | 「**半解**」＝这一期讲清的那一半 ／「**未解**」＝这一期还没搞定的那一半 |

**一句自省（别忘）**："今知"两字单独看无典可依，是"今日方知我是我"给了它出处与纵深。因此**名字与出处应成对出现**——简介、关于本站、落款处至少出现一次，否则读者看不懂这个名字。

## 卷首语 v3（2026-09-28，待老板终审）

> **卷首｜今知先生**
>
> 大模型的输出，像刚出厂的东西：表面光滑，参数齐全，看不出毛病。
>
> 但你看不见它里面。它不知道的东西，和它知道的东西，说出来的语气一模一样 —— 没有迟疑，没有停顿，也没有一次"这个我不确定"。老子说：知不知，上矣；不知，知，病也。不知道，却以为自己知道，这是它的病，也是它能给你漂亮答案的原因。
>
> 所以我不看它说得多顺，只看它跑起来是什么样。遇到不清楚的，先去跑一遍。
>
> 我干的是测试。这些年一直在给测试造工具 —— 让用例自己跑起来，让失败自己说清原因。
>
> 这里写两样东西。一样是我用 AI 做事的过程：哪一步成了，哪一步它开始骗我；能复现的，我把步骤写出来。另一样是做事时想到的东西 —— 关于工具和人，没有标准答案。
>
> 鲁智深听潮而悟，留下一句：钱塘江上潮信来，今日方知我是我。我也不是一开始就知道自己在想什么 —— 写下来，才慢慢认出来。
>
> 先跑一遍，再看结论。

**版本沿革**：**v2 已作废**（老板 2026-09-28 反馈"逻辑不通"）。病因诊断：v2 里并列了**四种含义不同的"知"** —— 老子的"知不知"讲知识上的自知，鲁智深的"方知我是我"讲认得自己的本性，"知道自己在想什么"讲认识自己的想法，"多解一点"讲解题理解。四个都好看，但**不是一条线，读着就断**；而且通篇 AI 只占一段，跑题成了哲理散文。

**v3 的修法（只留一条线）**：现象（光滑的答案）→ 病因（不知而自以为知）→ 我的动作（跑一遍）→ 写什么（技术过程 + 想到的东西）→ 名字出处（我为什么写）→ 落款。两个典故各归其位：**老子那句负责解释"危险在哪"，鲁智深那句负责交代"名字从哪来、我为什么写"**，不再平行并列。

**老板已否的写法（勿回退）**：① "我不是来揭它短的"（辩解句，显心虚）；② "我不是科班的"（老板：不用体现，没啥用）；③ 孙权劝学开场（太大众、与 AI 无关）；④ 结尾落在"看它答得顺不顺／记两样东西"（太直白、无余味）；⑤ 以"我造了一个 E2E 测试 Agent"自我介绍（说明书腔、简历动作）；⑥ v2 的四种"知"并列（逻辑不成线）。

## 卷首语 v1（老板亲笔原文，2026-09-26；定名后由 v3 替换，保留作史）

卷首｜水滴观测站

光滑的外壳，未必代表无懈可击。大模型与Agent智能体亦是如此。流畅的回答、看上去完备的任务规划之下，幻觉、工具调用错误、偶现的规划失效、版本能力退化常常隐匿于黑盒之中，并不轻易显露。

设立「水滴观测站」，便是希望以工程师的视角，持续试探、观测、核验智能背后潜藏的风险。

这里会记录Agent、MCP链路实测，分享AI端到端评测与质量度量的实战复盘，也会聊聊生成式AI时代质量范式的思考。

不迷信表象的顺滑，于黑盒之外，做一名冷静的观测者。愿所有的探索，从这一次次观测开始。

> **老板裁决（2026-09-28）**：这是一个**作品**，不是资产。目的是记录自己的思考总结、打造个人 IP；行业（ICT / E2E 测试 Agent）只是当下从事的领域、是素材来源，不是身份标签。因此**不为"持续留档同一批对象"设义务**（基线档案降级为偶尔的重头戏），**定位表述以"我是谁"为主、以"写什么"为辅**。详见 `定位复核与建议_v1.md` §九。

## 定位提炼（2026-09-28 重定，以此为准；上方"卷首语 v1"及 09-26 的旧表述已部分作废）

**(1) 写作性质：这是一本公开的练习本 —— 作品，不是资产。**

目的是记录自己的思考总结、打造个人 IP。**方法是费曼学习法：输出倒逼输入**；检验标准是"我讲清楚了吗"，不是"我记全了吗"。**不追求粉丝量，自己有成长就行**。因此：不背"持续留档同一批对象"的义务（基线档案降级为偶尔的重头戏）；不设"受众定位"这道题（既不收窄也不放宽）；不必为行业代言。

**(2) 身份：一个非 AI 专业出身、对 AI 乐观的测试开发工程师。**

- **本职是测试开发** —— 写测试工具的人，不是写用例的人（传统测试体系并非所长，也不往那边靠）。十年里干的是"让用例自己跑起来"的那套东西。
- **亲手造了一个 E2E 测试 Agent** —— 内容从"造"出发，按链路环节拆（最深的两段：**脚本生成**、**自动调测**），"E2E"作为收口。
- 不是某个领域的专家，而是"什么都感兴趣、都自己动手试、试完老实说结果"的人。
- **"非专家"是人设本身，不是需要弥补的短板。**

**(3) 姿态：看清了，还敢用。**

乐观、甚至激进。观测是**手段**，不是立场 —— 不是"因为不信它才观测"，而是"想把它用得更好，所以看清它"。这是与"冷静的观测者/不迷信表象的顺滑"的区别所在。

**(4) 内容配比：技术与思考五五开。**

- **技术篇** → 交付**可照着复现**的步骤与判断依据（这是他定的读者价值，也是选题第一筛子）；
- **思考篇** → 交付**一个角度，或一个我还没想明白的问题**（没有标准答案）；
- 绑住两半的线是"**我**"：思考类尽量从正在做的事上长出来，避免散成杂谈。
- 兴趣支线（都会写）：端侧模型 / 本地知识库 / 用 AI 出东西（PPT·视频·图）/ **机器人（长期看好，仿真先行）** / AI 辅助教育（OpenMAIC，自家孩子的真问题）/ AI 分析（股票、合规边界内）/ 历史与典籍（大秦帝国、三国、明史、宋史、道德经、周易）。

**(5) 不带的东西**：不写公司与行业标识、不做行业代言、不消费前东家、不追热点标题党。

**(6) 人设是底色，不是每篇的清单**（老板明确纠正）：不刻意在每篇里"体现人设"；人设的正确用法是**写完核**——核有没有与人设**相悖**的东西（装权威、吹牛、不认账），而不是核有没有体现到位。人设在累积里自然成立。

**旧表述（2026-09-26，部分作废，保留作参照）**：一句话定位曾写作"以工程师视角，试探、观测、核验大模型与 Agent 背后的风险——做黑盒之外冷静的观测者"；目标读者曾定为"关注 AI 工程化、测试、质量的工程师与技术人员"。二者已被 09-28 重定取代：**"黑盒之外"的旁观姿态与"乐观动手造"的底色不符；受众问题已作废。**

## 内容策略（2026-09-26 老板定调）

- **热点切入优先**：评测/思考/洞察类文章从最新热点切入（新模型、新工具、行业事件、热文争议），借势落笔，再收回到自己的观测——不写"大家都能写的通用内容"
- **独有底牌**：老板主业即 E2E 测试 Agent（ICT 通信行业），测试设计、用例、脚本、调测、自动化连跑每个环节都有一手体感。这是"观测站"最深的护城河——全网几乎无人从通信 E2E 测试工程视角写 AI
- **脱敏纪律**：涉及工作素材只写方法、现象与思考，不写公司名、项目名、客户与数据细节

## 四大内容支柱

1. **Agent / MCP 链路实测**：第一手测试记录与踩坑复盘
2. **AI 端到端评测与质量度量**：工具（browser-use、DeepEval、promptfoo、agentevals 等）实战与方法学
3. **质量范式思考**：生成式 AI 时代测试与质量的理念观察（如杰文斯悖论 × 测试）
4. **组织与人的转型**：Agent 时代对团队结构、质量职能、工程师角色的影响——团队转型路径、"超级工程师"（一人 + Agent 编队）的兴起与代价、测试工程师的角色迁移（从写用例到设计评测）

> 支柱 4 的写法约束：仍以观测者/工程师视角切入，从实测现象推导组织变化，讲"看到的证据 + 判断"，不写空泛管理论和职场鸡汤。

IP 战略（顶层逻辑）：**个人 IP 是唯一北极星**——人物（通信 E2E 测试一线工程师）> 原创框架（四层失效分类学）> 固定仪式（文风/档期/结尾句）> 栏目名。付费是 IP 做成后的自然延伸，不进设计主轴。
IP 认知漏斗：看见（周报）→ 认出（洞察）→ 信任（实战）→ 跟随（转型）→ 连接（读者案例/访谈）。

## 文风要点（写稿时遵循）

- 工程师口吻，冷静克制，不吹不黑、不搞营销号标题党
- 用证据说话：实测数据、失败案例、复现步骤优先于观点
- 常用词汇：观测、实测、核验、试探、复盘、黑盒、链路、退化
- 有观察者的疏离感和专业感，允许适度文学性收尾（参考卷首语气质）
- 禁用：浮夸惊叹号堆砌、"震惊体"、空洞趋势口号

## 竞品写作情报（2026-09-26 调研）

- **赛道现状**：Agent 评测内容正在升温。美团 9/10 发《Agent 评测全览》、大淘宝 9/18 发业务效果评测实践、Anthropic 有《Demystifying evals for AI agents》长文，9 月下旬多个公众号在跟进解读
- **头部写法（值得学）**：
  - 解读派（AItest进阶之路 9/24《Anthropic这套Agent评测体系,太牛了》）：先给认知反转（"我们在测错对象"）→ Outcome/Transcript 二分 → pass@k vs pass^k → 自建六层框架 → 结尾"定义成功比打分更难"升华 + 资料钩子（后台领清单）+ 求关注
  - 实践派（人与硅基杂记 9/20《为什么Agent评测成了各大厂的必争之地》）：开头即严谨声明（材料来自公开披露非实测）→ 用美团 PPT、淘宝位置偏差案例说话（96% 训练/50% 验证的判分器翻车）→ 分节推进 → 文末附参考资料链接
- **差异化空档（水滴观测站的打法）**：
  1. 大家都在解读论文和大厂实践，几乎没人做**第一手实测**（自跑 browser-use/PageAgent 记录真实失败）
  2. browser-use 类公众号内容全是"工具介绍/上手教程"，没人从**失效/质量视角**写
  3. 视觉 Agent（截图派 vs DOM 派）的对比实测完全空缺
  4. 我们的优势：观测者人设 + 失效分类学框架 + 拒绝伪造数据的纪律
- **注意**：Anthropic 的 Outcome/Transcript、pass@k/pass^k、黄金集/错题集等概念已是赛道公共知识，我们引用时正常署名即可，不必回避；四层失效分类学是我们自己的框架，是差异化资产
