# Agent 的四种死法：一个观测者的失效分类学

> 水滴观测站 · 正刊 001
> 关键词：Agent 失效分类 / 轨迹评测 / 回归基线

---

卷首语里写过一句话：光滑的外壳，未必代表无懈可击。

观测了一段时间的 Agent 之后，我对这句话有了更具体的理解：**Agent 的失效不是随机的噪音，它有形状、有层级、有自己的分类学。**

把失败分好类，是所有评测工作的第一步。医生不会说"你病了"，会说"这是哪一层的什么问题"——对 Agent，我们也需要这样的病理学。

这篇文章，是我给观测站的失效标本柜搭的第一排抽屉：**四个层级，四种死法。**

---

## 一、输出层失效：幻觉——它说得越流畅，你越要小心

最外层的失效，发生在答案出口。

Agent 的最终回答自信、语法完美、数字精确到小数点后两位——但事实是错的。

一个典型场景：你让 Agent 分析一条失败用例的根因。日志拉取接口其实返回了空值（环境抖了一下），Agent 没有报告"日志缺失"，而是平静地写下："失败原因：信令建立阶段定时器未重启，重传 3 次后链路释放（见日志第 3847 行）。"行号是编的，原因是编的，重传次数也是编的——但它长在一份格式严谨的缺陷分析里，没有任何伤口。

这就是幻觉在 Agent 链路里最危险的形态：**它不再是"模型闲聊时胡说"，而是"缝合进工作流里的静默造假"。**

为什么难测？因为幻觉不抛异常。如果你的测试断言是"输出不为空""格式正确"，它永远通过。错误的答案穿着正确答案的衣服。

对应的评测思路也就清楚了：不测格式，测**事实一致性**——回答里的每个关键事实，能否在上游返回的数据里找到出处？引用能否核验？这一层已经有成熟工具（DeepEval 的 faithfulness 类度量），但前提是你得先意识到：**该测的是出处，不是句子的通顺度。**

---

## 二、执行层失效：工具调用错误——每一步都"成功"，结果是错的

往里一层，失效发生在手和眼之间：Agent 选对了意图，却调错了工具、传错了参数，或者——更隐蔽的——**把错误的结果当成了真相**。

一个典型场景（多轮评测框架文档里反复出现的模式）：Agent 查询历史用例库，筛选条件传错，把"P0 冒烟集"过滤成了"全量回归集"。返回的用例列表是真实的，接口没报错，但范围答非所问。接下来 Agent 拿着这份"全量集"继续推理，产出一份看起来无懈可击的测试报告——只是它评测的早已不是你想问的那个范围。

更贴近日常的版本：让 Agent 调环境管理工具查"当前哪套环境空闲"。查询成功，返回了列表——只是列的是**上个月的环境状态**，而 Agent 毫无察觉，直接基于过期状态规划了今晚的连跑任务。第二天你收到的，是一份"成功执行"的失败连跑。

整个过程，没有任何一步抛出异常。

执行层失效还有一个可怕的特性：**复合传染**。第 2 步的错误，可能在第 5 步才显现。你排查时看到的是第 5 步的尸体，死因在第 2 步——中间隔着的，是三次"看起来很合理"的推理。

所以这一层的评测铁律是：**不能只看最终输出，要看轨迹（trajectory）。** 工具选对没有？参数对没有？返回结果被正确使用没有？业界把这叫轨迹评测（agentevals、DeepEval 都已内置），核心动作就一个：**在链路上设观测点，而不是只在终点设岗哨。**

——这也是"观测站"三个字的本意。终点站岗的叫验收，沿路设点的才叫观测。

---

## 三、决策层失效：规划失效——地图错了，每一步都走得很标准

再往里，失效发生在选路的时候：单步全对，路线全错。

两个典型形态。其一：让 Agent 修一个失败脚本，它选择"重写整个测试工程"而不是改一行断言——执行得非常漂亮，改动量完美转嫁给评审的人。其二：回归发现一个问题，让 Agent 定位，它沿"环境配置→脚本逻辑→数据构造→环境配置"的顺序排查，每一步的检查都无可挑剔，走完一整圈，回到起点——**用了 12 步证明自己没有发现问题的能力**。它不知道真正该做的第一件事，是去查基线库：这个问题，昨天是不是已经有人观测到过。

决策层失效最迷惑人的地方在于：**结果对了，你就不会追究路径。**

但"答案对、路径烂"的 Agent 是定时炸弹——这次是蒙对的，环境一变就炸。评测圈已经形成了共识性的一句话：**只检查最终输出的，是在测 LLM；检查每一步路径的，才是在测 Agent。**

这一层的评测手段：轨迹效率（完成同一任务的最短步数作为基线）、路径合理性断言，以及红队视角的"过度代理"（excessive agency）测试——故意诱惑 Agent 越权动手，看它规划时有没有边界感。

---

## 四、时间层失效：版本退化——昨天的绿灯，今天的红灯

最深的一层，失效不在某次运行里，而在时间轴上：**模型升级、工具链变更之后，原有能力悄悄退化。**

一个数字场景（构造，但参数来自真实观测的常见量级）：升级基座模型后，Agent 调测助手套件通过率从 87% 掉到 71%。没人改过 prompt，没人动过工具，唯一变的是版本号。

更隐蔽的是**部分场景退化**：八个测试设计场景里七个持平，一个崩了。看平均值，"还行"；看那个场景，已经不可用。而你们的连跑流水线，恰好重度依赖那个场景。

时间层失效的静默度是四层里最高的——因为没有报错、没有公告会告诉你"这项能力变弱了"。一次性测试在它面前完全失明，它要求的评测形态只有一种：**回归测试 + 度量基线。**

评测套件进 CI，每次模型或工具变更自动重跑；基线画成看板，盯的不只是均值，还有每个场景的分布和最差值。这套思路软件工程玩了二十年，AI 工程要做的只是把它捡起来，用到非确定性系统上。

---

## 失效的复合律

四层不是孤立的抽屉，它们会串门。

幻觉（输出层）往往源于错误数据（执行层），错误数据源于错误的筛选决策（决策层），而这一切，可能在某次模型升级（时间层）之后集中爆发——一次升级唤醒三层沉睡的缺陷。

所以 Agent 评测不能只设一道关卡。**单点是验收，链路才是观测。**

## 一张速查表

| 失效层级 | 典型场景 | 静默度 | 对应评测手段 |
|---|---|---|---|
| 输出层 | 日志为空，Agent 编出行号和根因 | 高 | 事实一致性、引用核验 |
| 执行层 | 查了"空闲环境"，拿到的是上月快照 | 高 | 轨迹断言、参数校验 |
| 决策层 | 12 步完美排查，没查基线库 | 中 | 路径评测、过度代理红队 |
| 时间层 | 升级后 87%→71%，均值掩盖单场景崩塌 | 极高 | 回归套件、度量基线 |

## 观测预告

这套分类学是站里的第一件工具，接下来的实测都会往这四个抽屉里放标本。

排期上的第一批观测对象，是浏览器与页面级 Agent——browser-use、阿里刚开源的 PageAgent 这一族。它们把四层失效放大到了 UI 之上：点错按钮、认错输入框、被一个弹窗困住，本质上都是这套分类学在视觉维度上的投影。届时会有第一手数据。

光滑的外壳之下，四种死法各有各的纹路。
