## 三、老板要做的两件事：启用 AppSecret + 配 IP 白名单

> **入口已变更（2025-12 起）**：AppSecret 不再在 `mp.weixin.qq.com` 的【基本配置】里启用，改到 **微信开发者平台**。
> 路径：**微信开发者平台（developers.weixin.qq.com）→ 用管理员微信扫码登录 → 我的业务 → 公众号/服务号 → 基础信息 → 开发密钥** → 点【启用】（或重置/冻结）。
> 旧入口若还能进，也会引导到这里。**启用/重置都要管理员扫码确认，且 AppSecret 只显示这一次。**

**启用时会遇到两种提示，各对应一种解法**（官方口径）：

| 提示 | 原因 | 解法 |
|---|---|---|
| "该账号尚未完成**实名**，前往微信公众平台完成实名后重试" | **个人主体**账号未完成管理员实名 | 微信公众平台 →【设置与开发】→【人员设置】→【管理员信息】补实名。**判断方法**：账号详情 → 主体信息，显示管理员姓名即为已实名 |
| "该账号尚未完成**主体认证**，前往微信公众平台完成认证后重试" | **非个人主体**账号未完成微信认证 | 需走微信认证（付费）；个人主体不会遇到这条 |

**2. 配 IP 白名单**（AppSecret 启用后，白名单区块才可填）
同一页找【IP 白名单】→ 添加**实际调用 API 的机器**的公网 IP（本机查：`curl ifconfig.me`）。
漏配的报错是 `40164 invalid ip` / `ip not in whitelist`，**换网络后要重新加**。

**3. 必读：权限风险（决定主路径选哪条）**
微信官方对 **草稿箱接口（`draft/add`）的适用范围写的是"仅认证"**——未认证账号调用会返回 `48001 api unauthorized`，且个人主体**无法微信认证**。
但社区里确有未认证账号调通的零星案例（官方口径与实现不完全一致）。

**所以策略是**：账号类型允许就用 API 推草稿箱；**一旦报 48001，立刻切路径 B（复制粘贴），不要在这上面纠缠**——反正发布本来就必须人工点。

**4. 凭据安全纪律（硬性）**
- **AppID 与 AppSecret 一律不入库、不入聊天窗口、不写进任何 `.md`**——只落本机 `.env.secret`（`.gitignore` 已排除 `.env.*`）或 `wenyan credential -s`（存于 `%APPDATA%\wenyan-md\credential.json`，在仓库之外）；
- 推送命令加 `--env-file .env.secret`，无需把密钥写进任何脚本；
- 若 AppSecret 曾在聊天/群里出现过，**立刻重置**一次；
- 原始 ID（`gh_` 开头）与公众号主页链接属半公开信息，可以入库，见 `公众号账号信息.md`。

## 六、故障排查

| 报错 | 原因 | 处理 |
|---|---|---|
| `48001 api unauthorized` | **账号未认证**，草稿箱接口无权（个人订阅号最常见） | 不再纠缠 → 切路径 B（render + 手动粘贴）；发布本来就必须人工 |
| `40164 invalid ip` / `ip not in whitelist` | 公网 IP 未加白名单（或换了网络） | 后台加 IP，再重试 |
| `未能找到文章封面` / `title is required` | frontmatter 缺 `cover` 或 `title` | 补齐 frontmatter（见 §四） |

| `wenyan: command not found` | 不在 PATH | 用 §二 的 `export PATH` 那行 |
| 图片没上传 | 走的 render 路径 | 手动在编辑器里传图；或改用 publish（凭证配好后） |

## 八、实测记录（2026-09-27）

**测法**：拿一份测试稿 + 老板提供的 AppID + Secret 跑 `wenyan publish`，看微信返回什么。

| 试法 | 结果 | 结论 |
|---|---|---|
| `--env-file <路径>`（POSIX / Windows / 相对 三种写法） | 均报"未提供 AppID：请通过参数、环境变量或配置文件指定" | ❌ 该参数不生效，别用 |
| `--app-id wx...` | 报"未能找到 AppID 为 wx... 的公众号凭据，请检查配置文件" | ⚠️ 该参数只用于挑选**已存好的**凭据，不能首次传参 |
| **环境变量 `WECHAT_APP_ID` + `WECHAT_APP_SECRET`** | **真打到了微信服务端**，返回 `40164: invalid ip 36.163.154.184 ... not in whitelist` | ✅ **这是可行路径**；同时暴露出下一道门槛是 IP 白名单 |

**🔑 实测得到的关键信息：本机当前出口公网 IP = `36.163.154.184`**
→ 这就是要加进公众号后台 IP 白名单的地址（由微信在 40164 报错里回显，比自己查更准）。

### 白名单 IP 怎么管（会变，别只加一个）

`36.163.154.184` 的归属：**中国移动 CMNET（AS9808，网段 36.163.128.0/17）**——即本机当前所在宽带的**公网出口 IP**，不是电脑的固定地址。

- **动态性是常态**：家庭/办公宽带多为动态公网 IP，重启光猫路由或运营商重新分配后会变 → 白名单随即失效，又报 `40164`；
- **白名单支持加多个 IP**：建议把常用出口都加上（家里、公司、手机热点），减少"换个地方就推不动"；
- **每次推送前跑一次 §九 的自检脚本**：它会回显当前出口 IP，和后台列表不一致就去补加；
- 若嫌烦，长期方案是把推送动作放到固定 IP 的云主机上——**本号不值得**（未认证号大概率无草稿箱接口权限，本来就要走复制粘贴路径）；
- 风险提示：IP 本身不是密钥，公开风险低；但也别在公开渠道晒后台截图。

**下一步顺序**：
1. ✅ AppSecret 已启用并填入本机 `.env.secret`（32 字符）
2. ✅ 后台 IP 白名单已加 `36.163.154.184`（`40164` 已消除）
3. ✅ 自检通过：`access_token` 获取成功 + `draft/count` 正常
4. ✅ **端到端推送实测成功**（见 §十）
5. ⏳ 唯一剩余：等 001 定稿 → 走 §二 路径 A 推送

### 端到端验证记录（2026-09-27 23:10）

| 步骤 | 命令/接口 | 结果 |
|---|---|---|
| 1 凭证+白名单 | `/cgi-bin/token` | ✅ 拿到 access_token |
| 2 接口权限（**只读探测**） | `/cgi-bin/draft/count` | ✅ `{"total_count":1}` → 草稿箱接口**可用** |
| 3 端到端推送 | `wenyan publish -f 测试稿.md -t lapis` | ✅ `发布成功，Media ID: F7c2ff…`（封面图已自动上传图床） |
| 4 清理 | `/cgi-bin/draft/delete` | ✅ `errcode: 0 ok`，草稿箱恢复为原有 1 条，不留测试垃圾 |

**两条值得记下的结论**：
1. **"未认证号不能调草稿箱接口"的官方口径，至少对本号不成立**——实测可调、可建、可删。所以主路径定为 **API 推送**，render 复制粘贴退为备用；
2. **验证时用只读接口探权限**（`draft/count`），不要拿"能不能建草稿"去试——既省一次垃圾清理，也不会污染草稿箱。

```bash
cd "C:/code/personal/dropseer"
```

**无副作用**（只调 `/cgi-bin/token` 取 access_token，不建草稿、不发消息、不传图），并把错误码翻译成下一步动作：

| 返回 | 含义 | 动作 |

| `40013` | AppID 无效 | 核对 AppID |
| `48001` | 接口未授权 | 账号无草稿箱权限（未认证），切 §二 路径 B |
