# 水滴观测站 · 自定义菜单设计 v1（提案）

> 2026-09-27 制定。上游：《内容系列架构 v1.1》（六栏目）、《卷首语与定位》。
> 用法：本文是**提案**，老板点头后按 §五 的落地顺序在后台执行。菜单是可随时改的，不用一次到位。

---

## 一、先搞清权限：你这号能做什么、不能做什么

水滴观测站是**个人主体订阅号，未完成微信认证**。这一条决定了菜单的设计边界（腾讯客服口径）：

| 能力 | 未认证订阅号 | 说明 |
|---|---|---|
| 一级菜单 | 最多 **3 个**，名称 **≤4 个汉字** | 官方口径 4 汉字/8 字母；部分账号后台已放宽到 5 汉字，以实际提示为准 |
| 二级菜单 | 每个一级下最多 **5 个**，名称 **≤8 个汉字** | 同上，部分账号放宽 |
| 动作一：发送消息 | ✅ 可用（图文 / 图片 / 语音 / 视频） | ⚠️ **不支持"纯文字"类型**（认证号才有） |
| 动作二：跳转网页 | ⚠️ 受限：**只能填公众号体系内的链接** | 即：页面模板 / 合集 / 已发表图文 / 历史消息页。**外部网址填了也存不了** |
| 跳转小程序 | ❌ 暂不适用 | 需关联小程序，目前没有 |
| 生效时间 | 点【保存并发布】后同步 | 官方口径 24 小时内；实测通常几分钟。粉丝**不会**收到更新提示 |

**三条推论**（决定了整套设计）：

1. **菜单只能指向"合集/页面模板/已发表图文"这三类链接** → 所以菜单的骨架应该是"**栏目合集**"，而不是一篇篇具体文章；
2. **一级菜单有两个身份**：没有子菜单时可以设点击动作（一键直达），有子菜单时点击它没反应 → 所以"最想让人一点就走的那一项"应该做成**叶子一级菜单**；
3. **资料类内容没有文件直传通道** → 只能走"图文说明 + 后台回复关键词/阅读原文"的老办法（见 §三）。

## 二、菜单设计（3 个一级 × 最多 5 个二级）

### 一级 1 ｜**本周周报**（叶子菜单，直接跳转，无子菜单）

| 项 | 内容 |
|---|---|
| 名称 | 本周周报（4 汉字） |
| 动作 | 跳转网页 → **热点周报合集** |
| 为什么 | 周报是唯一"每周固定档"的栏目，也是回头客的主要入口。做成叶子一级 = **一点就到**，不用展开二级 |
| 前提 | 周报合集的链接要先存在（见 §五 落地顺序）。试刊期可先临时指向"最新一期" |

### 一级 2 ｜**按栏目读**（5 个二级，正好对应六栏目里的五个）

| 二级名称 | 动作 | 指向 |
|---|---|---|
| 洞察思考 | 跳转网页 | 洞察思考合集 |
| 技术实战 | 跳转网页 | 技术实战合集 |
| 团队转型 | 跳转网页 | 团队转型合集 |
| 读者案例 | 跳转网页 | 读者案例合集（先建空合集，等来稿；也可暂缓上架） |
| 全部文章 | 跳转网页 | 历史消息页 / 页面模板（总目录） |

> **同行访谈**（储备栏目）**不进菜单**，等真要启动再加——菜单位只有 5 个，别给空栏目占位。
> 为什么把"技术实战"放在第二而不是第一：读者从周报进来后最想看的是洞察（被记住）和实战（立信任），团队转型更靠后，顺序按认知漏斗排。

### 一级 3 ｜**领资料**（4 个二级）

| 二级名称 | 动作 | 指向 |
|---|---|---|
| 失效清单 | 发送消息 → 图文消息 | 指向一篇《Agent 失效检查清单》说明图文（后台回复关键词"失效清单"自动发资料） |
| 观测协议 | 发送消息 → 图文消息 | 指向《观测协议》说明图文（002 上线后启用，前期留空或先写预告） |
| 关于本站 | 跳转网页 | 卷首语（已发表图文，作为账号的"第一页"） |
| 投稿联系 | 发送消息 → 图文消息 | 读者案例征集说明（含联系方式与脱敏要求） |

> "失效清单"和"投稿联系"为什么用**发送消息→图文消息**而不是跳转：因为资料/联系方式不属于"公众号体系内链接"，只能用发图文的方式承载，再让读者在图文里按提示回复关键词或点"阅读原文"。

## 三、两个坑，先讲清楚

### 坑 1：菜单别指向单篇文章，一律指向合集

菜单里的链接是**静态**的——你今天填了 001 的链接，三个月后它还指向 001。指向**合集**则内容自动累积、自动按时间排序，**菜单一次设置、长期不用改**。唯一例外是"关于本站"这类固定锚点（卷首语永远只有一篇）。

### 坑 2：资料不是"点一下就到手"，中间必须有一个动作

未认证号没有文件下载通道，外链也进不来。行业里通用的做法是这条链路：

```
菜单【失效清单】→ 弹出图文《这份清单怎么用》→ 文末提示"后台回复「失效清单」"
→ 自动回复里给出网盘链接（纯文本，读者复制）
```

**必须提前配好两样**：一篇说明图文 + 一条关键词自动回复。只配菜单不配回复，读者点了会一脸问号。

## 四、菜单与栏目规划的对应关系（一眼核对）

| 栏目（六系列） | 菜单位置 | 状态 |
|---|---|---|
| 热点周报 | 一级「本周周报」 | 试刊后上架 |
| 洞察思考 | 二级「洞察思考」 | 001 发布后上架 |
| 技术实战 | 二级「技术实战」 | 002 后逐步填充 |
| 团队转型 | 二级「团队转型」 | 009 前后上架 |
| 读者案例 | 二级「读者案例」 | 有来稿再上架 |
| 同行访谈 | —（不进菜单） | 5000 常读后启动再议 |
| 配套资料 | 一级「领资料」 | 与 001 同期上线 |

## 五、落地顺序（七步，前四步在内容侧，后三步在后台）

1. **建合集**：后台【内容管理】→ 创建 5 个合集：热点周报 / 洞察思考 / 技术实战 / 团队转型 / 读者案例（每个合集最多可放 1000 篇）
2. **把已发表文章归入合集**：发文时勾选合集即可，**历史文章要手动补归**
3. **做"总目录"页面模板**（若后台可用）：列表模板最多 30 篇；综合模板上半 3 篇 + 下半 5 分类 × 每类 30 篇 → 作为二级「全部文章」的落点
4. **配资料链路**：写《失效检查清单》说明图文 → 配关键词自动回复（回复"失效清单"）
5. **后台填菜单**：公众平台 → 【内容与互动】→【自定义菜单】→ 添加菜单 → 填名称 → 设菜单内容 → 逐个设完
6. **点【保存并发布】**：不发布不生效
7. **用另一个微信号验证**：菜单要"取消关注再关注"或等几分钟才刷新；一级菜单有子菜单时点击无反应是正常的，别以为是坏了

> **顺序很重要**：先有合集链接，才能往菜单里填。第 1–3 步没做完就动菜单，只会填进去一堆死链。
> 另外，试刊期不必等六个栏目都齐——**先上"本周周报 + 领资料"两个，第三格留空**，等 001 发布后补齐，比一次上满但大半是空合集好。

## 附：一句话总结

**这个号的菜单不需要"花活"，它只需要三个动作：一点看周报、按栏目翻文章、进来领资料。**
六个栏目正好装满两格（周报占一格 + 五个栏目占一格），第三格留给资料与关于——**菜单是货架，不是招牌，越朴素越好用**。
